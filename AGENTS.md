# AGENTS.md — Reqour

## Project Overview

**Reqour** is a Quarkus-based rewrite of [Repour](https://github.com/project-ncl/repour), serving as the SCM repository manager and alignment engine inside the [Project Newcastle (PNC)](https://github.com/project-ncl) build system. It has two primary responsibilities:

1. **SCM Repository Creation** — creates and synchronises downstream Git repositories inside the PNC workspace (backed by GitLab or GitHub).
2. **Alignment** — clones a source repository, runs the appropriate build-tool manipulator, pushes the aligned changes back to the downstream repository, and sends a callback to the caller.

The project is licensed under Apache 2.0 and targets **Java 21** with **Quarkus 3.x**.

---

## Module Structure

The repository is a Maven multi-module project.

```
reqour/
├── pom.xml              # Parent POM — dependency management, build plugins
├── core/                # Shared library (not deployed standalone)
├── rest/                # reqour-rest: HTTP service (JAX-RS / Quarkus REST)
└── adjuster/            # reqour-adjuster: CLI app run as an OpenShift Job
```

## Key Architectural Patterns

### Git Provider Abstraction

Exactly one Git provider (GitLab **or** GitHub) is enabled at runtime, enforced by `@WithExactlyOneProviderEnabled`. URL translation and repo creation are provider-specific but share common interfaces in `core/service/`.

### Process Executor

All external processes (git, manipulators) go through `ProcessExecutor`, which streams stdout/stderr to configurable consumers and returns the exit code.

### CDI is build-time (Quarkus Arc)

Dependency injection uses **Quarkus Arc**, which resolves CDI at **build time** (Jandex index + generated bytecode) — *not* via runtime reflection and dynamic client proxies like Weld. Do not assume classpath scanning, runtime reflection, or proxy-based behavior:

- Beans in external dependencies are only discovered if that jar is Jandex-indexed (e.g. a `jandex-maven-plugin` marker or a `quarkus.index-dependency.*` entry). An un-indexed jar's beans are invisible.
- Reflection-based patterns that "just work" under Weld may need `@RegisterForReflection`.
- Bean wiring is validated at build time, so unresolved/ambiguous dependencies fail the build rather than at startup.

## Code Conventions

- **Formatting**: Spotless with Eclipse config. The `apply` goal is bound to the `compile` phase, so any build reformats the code. CI runs the `check` goal and **fails on violations** — run `mvn spotless:apply` before pushing.
- **License header**: Every `.java` file must start with the SPDX Apache 2.0 header; the `check` goal is bound to the `verify` phase and **fails the build** if a header is missing. Run `mvn license:format` to add them.
- **Exceptions**: Domain-specific exceptions (`GitException`, `AdjusterException`, etc.) map to `FAILED`; unchecked `Exception` maps to `SYSTEM_ERROR` in callbacks.
- **Lombok**: Prefer immutable types — annotate value/DTO classes with `@Value` (not `@Data`, which is not used in this codebase). For types deserialized from JSON, combine `@Value @Builder @Jacksonized`. Use `@Slf4j` for loggers rather than declaring a `Logger` by hand. `@Getter`/`@ToString`/`@EqualsAndHashCode` are used selectively; setters are effectively absent — avoid adding mutable state.

### Commit & PR conventions

- Commit subjects are prefixed with the Jira issue key in brackets, followed by an imperative summary: `[NCLSUP-1762] Keep git provider tokens out of answers`. All commits on a branch typically share the same issue key.
- PRs are merged into `main`.

### Testing conventions

- Tests live under `<module>/src/test/java`. Sample projects under `adjuster/src/test/resources/projects/...` are **fixtures** for manipulator tests, not application code.
- Naming controls *when* a test runs:
  - `*Test.java` → **surefire**, runs at the `test` phase (`mvn test`).
  - `*IT.java` → **failsafe**, runs at the `integration-test`/`verify` phase (`mvn verify` or `mvn install`), **not** by `mvn test`. Note these `*IT` classes are still annotated `@QuarkusTest` (in-JVM), not `@QuarkusIntegrationTest`.
- Run a single test: `mvn test -pl <module> -Dtest=ClassName#method` (use `-Dit.test=` with `verify` for `*IT` classes).
